# Recipes

A recipe is an ordered list of steps that applies corpus layers to one data
directory through the real `bookmole` binary. This file is the format.

The corpus is built from **layers**. A layer is one avenue into the library
(epubs, a calibre library, KOReader sidecars in the modern or legacy layout,
KOReader statistics, a Goodreads export, a reader's typed commands) at one
level of realism, generated by `crates/corpus` into its own directory under
`corpus/generated/<layer>/` and pinned by its own lock. Hostile values are not a
layer: they are salted into every layer at a declared, low proportion (at most
one per row, at most 5% of rows), each occurrence tagged in that layer's
manifest with its `crates/corpus/hostile.json` case id, so a failure names the
case and the layer. A recipe composes layers; `everything` is all of them.

The layers are committed. `make corpus-layers` regenerates every one in order
(`gen-calibre` needs calibre installed), and `cargo run -p corpus -- --help`
lists the generators one by one.

```
cargo run -p corpus -- build-recipe <name> --data-dir <empty dir> [--update-expect]
make corpus-build RECIPE=<name> [EXPECT=update]     # same, into target/corpus/<name>
make corpus-verify RECIPE=<name>                    # the invariant suite on a fresh build
```

## Files

- `<name>.toml` — the recipe (committed, small). The file name is the recipe's
  `name`; a test asserts they agree.
- `expect/<name>.json` — the **semantic lock** a build must reproduce
  (committed): counts of books, highlights (and how many are attributed to a
  reading), notes, `notes_fts` rows, note links, flashcards, readings by
  status, covers, `user` provenance rows; every title, sorted; and one entry per
  salted hostile case with its exit code and whether that is what was declared.
  Nothing the clock decides is in it.
- `dump/<name>.txt` — optional: a frontend's deterministic text dump of every
  screen over the built library, normalised:
  the data dir's path becomes `<data-dir>`, lines naming a date within a day of
  the build are dropped, `home.moment` (which picks among rows created in
  the same second) is collapsed, the clock's year on the year wall becomes
  `<clock-year>`, and the children of `library.still-reading` and of each
  `library.year.<y>` (ordered by timestamps that tie within a build second or a
  day) are sorted, so the golden pins membership and each tile, not tie order.
  `UPDATE_GOLDEN=1` rewrites it. The invariant suite skips it when the frontend
  that produces it is not built.
- `fixtures/` — inputs a recipe needs that no generator writes yet (today an
  87-line `verbs.jsonl`, in `gen-reader`'s documented shape: a physical reader's
  typed pages, margin notes, overview and zettel notes, two corrections, and
  four salted rows — 4.6%, under the 5% salting cap, which a unit test in
  `recipe.rs` holds every committed verbs file to).

`personal_data/recipes/` (gitignored) holds recipes over your own data, a
private overlay; they are read the same way and keep their `expect/` and
`dump/` beside them, never here.

## Format

```toml
name = "physical-reader"            # = the file name
description = "One sentence: who this reader is."

[[step]]
kind = "goodreads-import"
csv = "corpus/generated/reader/physical.csv"   # repo-relative, always

[[step]]
kind = "verbs"
file = "corpus/generated/reader/verbs.jsonl"

[[known]]                           # strict expected divergence, see below
case = "page-negative"
why = "progress stores a negative page (engine bug)"
```

| `kind` | input key | what the runner runs (after `bookmole --data-dir <dir>`) |
|---|---|---|
| `epubs` | `dir` (+ optional `limit`) | `epub <file>` for each `*.epub`, in file-name order |
| `calibre-import` | `library` | `calibre import --library <library>` |
| `ko-sync` | `root` | `ko sync <root> --all` |
| `ko-stats` | `mount` | `ko stats <copy>` — the mount is copied under `<dir>/.mounts/`, every `X.sql` becomes `X.sqlite3` through the `sqlite3` CLI, and the KOReader install markers are created; a mount with no `koreader/` dir is read as the settings dir |
| `goodreads-import` | `csv` | `goodreads import <csv>` |
| `verbs` | `file` | one invocation per `verbs.jsonl` line: its `argv`, verbatim |
| `refill` | — | `activity --refill` |
| `sort-keys` | — | `sort-keys` |
| `covers` | — | `covers` |

Per-step keys:

- `expect_failure = true` — the step must exit non-zero (a refusal that is the
  point). A panic (exit 101) is never an acceptable failure.
- `reapply = false` + `reapply_why = "…"` — leave an import step out of the
  idempotency invariant. Only with a reason, and the reason should be a
  reported bug: today it is `epubs`, because importing an ISBN-less epub twice
  makes a second book. The exclusion is strict, like `[[known]]`: the suite's
  `excluded_steps_are_still_not_idempotent` re-applies each excluded step (its
  first three inputs) to a copy of the built library and fails once that
  changes nothing, so the exclusion is removed when the engine is fixed rather
  than outliving the bug.

`[[known]]` lists hostile cases whose observed behaviour contradicts the class
`hostile.json` declares. They are **strict**: the build fails if a listed case
stops diverging, so the entry is deleted (and the case promoted) in the change
that fixes the engine. The declaration in `hostile.json` is never edited to
match the engine.

### `verbs.jsonl`

One JSON object per line, replayed in order:

```json
{"argv": ["note", "--title", "Argv looking", "--", "--data-dir=/tmp/evil --quiet -v"], "expect": "ok", "case": "argv-looking", "why": "text after -- is text"}
```

`argv` excludes the binary and `--data-dir`; user text goes after `--`; books
are named by **ISBN or title fragment**, never by row id (ids follow import
order, so they move whenever a layer is added before this one). Prefer the ISBN
when the title is a fragment of another title. `expect` is `"ok"` (exit 0) or
`"fail"` (non-zero, not a panic). `case` is a `hostile.json` id or `null`.

The runner passes argv to `std::process::Command` — never a shell — with
`HOME`/`XDG_CONFIG_HOME` pointed inside the data dir, `EDITOR=true`, stdin
closed, and `BOOKMOLE_DATA_DIR`/`GOOGLE_BOOKS_API_KEY` removed, so neither
your own config nor a provider key reaches a corpus build.

## The six recipes

| recipe | avenue | builds from |
|---|---|---|
| `minimal` | ten epubs | `corpus/epub` |
| `device-reader` | epubs + KOReader sidecars + statistics | `corpus/epub`, `corpus/generated/modern`, `corpus/generated/stats/modern` |
| `calibre-only` | a calibre library | `corpus/generated/calibre/library` (`gen-calibre`, needs calibre) |
| `physical-reader` | Goodreads + typed verbs, no files | `corpus/generated/reader` (`gen-reader`) |
| `hostile` | the salted layers in full | as above |
| `everything` | all of it, in a reader's order | as above |

Changing a recipe's input path changes the lock: rebuild with `--update-expect`
and read the diff before committing it.
